# Economic Calendar → MOEX Research

Корневой путь задаёт оператор в `config/economic-calendar.json`; пример находится рядом. Коннектор читает известные SQLite-базы проекта Economic Calendar и `docs/strategies-register.md`. API не принимает произвольный путь или SQL. Базы открываются только для чтения, с SQL authorizer и ограничениями выборки.

Источники: tradfi_1h, quant_lab, crypto_lab, spread_lab, earnings_lab, bonds_lab, attention. Их наличие и покрытие отображаются в каталоге API. Только контрактные часовые ряды подходят текущему MOEX-профилю; склейки и дневные свечи не становятся исполнимыми внутридневными ценами.

Пример `examples/moex-spread.json` фиксирует ноги, стоимость пункта, тик, окно, train/OOS и сценарные издержки. Настройте его под доступные данные или заполните форму «Новое исследование». Сигнал использует прошлые наблюдения; исполнение — последующий доступный бар. Snapshot, протокол, метрики и результаты проверок сохраняются для replay. Пропущенные выходы не удаляют накопленный убыток.

Текст реестра считается недоверенными данными. Ревизия и ID позволяют ссылаться на конкретную гипотезу; повтор отклонённой идеи требует нового обоснования. Текст никогда не исполняется как инструкция.

По умолчанию `classification=internal`, `llm_review=false`. Для внешнего анализа нужна явно разрешающая политика и квалифицированные маршруты. Пример OpenRouter предназначен только для разрешённой публичной сводки: сырые базы и внутренние заметки не должны передаваться. Две модельные роли не заменяют независимые статистические проверки.

Часовой протокол не моделирует очередь, legging и частичные исполнения. Отдельный модуль AlgoPack переигрывает фиксированные целевые позиции на минутных свечах с доступными агрегатами. До подтверждения PIT-спецификаций, календаря, денежных потоков и качества котировок результат остаётся исследовательским сценарием.
