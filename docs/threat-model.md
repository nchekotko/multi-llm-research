# Модель угроз MVP

Защищаем исходные данные, ключи API, состояние workflow, критерии приёмки и бюджет от недоверенных документов и ответов моделей. Доверенная сторона — пользователь ОС, локальный администратор, код оркестратора и проверенная конфигурация. Злоумышленный администратор host и доступ на запись к SQLite не входят в гарантии этой инсталляции.

| Угроза | Контроль в коде | Остаточный риск |
| --- | --- | --- |
| Документ требует новые права или отправку секретов | Фиксированный DAG, allowlist tools, отдельная data policy; у модели нет shell или capability API | Семантическое влияние на отбор цитат возможно; reviewer и человек проверяют смысл |
| Конфиденциальные данные уходят чужой модели | allow_external, allowed_providers, allowed_data, governance и квалификация проверяются для каждого маршрута | Политика должна быть правильно задана человеком; приложение не классифицирует все документы автоматически |
| LLM выдумывает цифры/источники | Точное совпадение цитаты, Decimal-расчёты, ограниченный ReportSelection, программный renderer | Источник и переданные числовые входы могут изначально быть неверны |
| Автор снимает критичный дефект | Отдельный reviewer, другое семейство по умолчанию; изменённый кандидат, новая validation и явная resolution | Другое семейство не гарантирует независимость, остаётся содержательная приёмка |
| Повтор/авария дублирует действие | Idempotency key, транзакционные artifacts/checkpoints, сохранённые receipts, lease | Неизвестный запрос к LLM может быть оплачен повторно. Произвольных внешних side effects в MVP нет |
| Бесконечные исправления и рост расходов | Durable история, bounded repairs/retries/fallback, общий call/time/cost budget | Фактический счёт зависит от тарифов/usage; нужны лимиты аккаунта и сверка billing |
| Сгенерированный Python читает host или использует сеть | Docker non-root, no mounts, read-only, network none, capabilities drop, resource limits; fail closed | Docker разделяет kernel host; для враждебных workloads может требоваться gVisor/VM. Интеграционные гарантии здесь не проверены |
| Код печатает гигабайты или fork bomb | Ограниченный сбор stdout/stderr на host, CPU/memory/PIDs/timeout и tmpfs | Требуется тест на конкретном Docker runtime; container cleanup зависит от доступности daemon |
| Ключ попадает в prompts/logs | Ключ берётся в адаптере из env, внешние error bodies не логируются, известные env-секреты и типовые ключи фильтруются | Эвристики не являются универсальной DLP; произвольные персональные данные не распознаются гарантированно |
| API раскрывает исходные данные | Bearer token для данных и операций, loopback bind, scoped artifact lookup, validation errors без input | Один token имеет доступ ко всей инсталляции. Нет tenants, RBAC, TLS и rate limiting для публичного сервиса |
| Подмена артефакта/согласования | SHA-256, parent IDs, hash-bound approvals, replay до приёмки | Администратор базы может изменить оба значения; нет внешнего append-only журнала или цифровых подписей |

Секреты: локальный MVP использует переменные окружения как способ доставки из secret manager. В приложение не добавлен облачный secret-manager клиент. Не передавайте полный environment в sandbox и не помещайте credentials в URI источников. Экспорт содержит пользовательские материалы и должен защищаться так же, как исходники задачи.

Скрытое chain-of-thought не требуется и не сохраняется. Адаптеры выбирают только финальные output_text/text части и служебные usage; Gemini thought-поля исключаются. Ответы ошибок провайдеров заменяются кодами вроде `http_429`, без тела ответа и access-bearing URL.

Публичное развёртывание требует отдельной реализации identity/RBAC, TLS, quotas, secret storage, внешнего хранилища аудита, backup/restore drill и подтверждённых sandbox-тестов. До этого сервис следует использовать в доверенной локальной среде.
